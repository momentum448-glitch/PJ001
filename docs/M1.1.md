# M1.1 - Facing and attack state

Status: Planned for implementation

## Validation question
Can the player clearly control attack direction on touch while repeated taps remain predictable and cannot overlap attacks?

## Locked behavior
- Facing is tracked separately from instantaneous velocity.
- Moving updates facing; releasing movement keeps the last facing direction.
- Basic attack uses facing only. No target auto-rotation in M1.1.
- Attack phases: startup -> active -> recovery.
- Melee hitbox exists only during the active phase.
- Attack input is ignored until recovery ends.

## Initial tunable values
- startup: 90 ms
- active: 90 ms
- recovery: 170 ms
- melee reach: 62 px
- melee hitbox size: 74 x 58 px

These values are tuning parameters, not locked product decisions.

## Device-test targets
- Direction of the strike is obvious before and during contact.
- Tapping ATTACK rapidly never creates overlapping strikes.
- Moving, releasing the stick, then attacking preserves the intended last facing.
- Controls remain comfortable after the small M0.7 size/position tuning.
